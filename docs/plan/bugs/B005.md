# B005: Preserve non-text successful LLM receipts

## Goal

Distinguish a successful non-text LLM response from an ordinary empty text
response without exposing provider tool arguments or reasoning as answer text.

## Scope

This standalone bug applies only to the non-streaming async receipt path. It
changes `LLMResponse`, its normalizer, and the existing agent and fan-out
receipt projections. It does not change provider billing, retries, fallback,
tool dispatch, or `stream_seam.py`.

## Acceptance criteria

1. A successful non-empty list of provider blocks with no genuine text returns
   `LLMResponse.text == ""` and `text_status == "non_text"`.
2. Empty strings, empty lists, and text blocks whose combined genuine text is
   empty return `text_status == "empty"`; visible string content returns
   `text_status == "text"`.
3. Only actual strings can enter `LLMResponse.text`. Mappings, lists, and
   scalars in provider content, including malformed `type == "text"` blocks,
   remain out of user-visible text and diagnostics.
4. A successful tool-use receipt preserves `tool_calls`, `finish_reason`,
   usage, and calculated cost while reporting the safe text projection.
5. `LLMAgent.run_async()` and `LLMService.call_llm_many_async()` retain
   `text_status` without copying raw provider blocks into workflow state or
   fan-out text.

## Verification

- `tests/fresh_suite/unit/services/llm/test_tool_call_extraction.py` covers
  normalizer status boundaries and structured-payload safety.
- `tests/fresh_suite/unit/services/test_llm_service_async.py` drives the real
  `call_llm_async()` receipt path through the client-factory seam, including
  tool-use metadata, usage, and cost.
- `tests/fresh_suite/unit/agents/test_llm_agent_async.py` and
  `tests/fresh_suite/unit/services/test_llm_service_fanout.py` cover the two
  receipt consumers.
