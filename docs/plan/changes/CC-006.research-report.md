# Research Report: CC-006 — Opt-in daily LLM call logging

## Scope

Assess the existing provider-attempt lifecycle, normalized usage and error evidence, LLM configuration, logging, and OpenTelemetry integration to determine where an independent local daily call log belongs. The requested record is one per physical provider attempt, including retries and fallbacks, with UTC-day filenames and nullable response/usage fields. It is disabled by default; retention and cleanup remain external.

Complex rigor is selected because the feature crosses provider invocation, retry/fallback lifecycle, configuration and dependency wiring, local filesystem writes, and the existing telemetry boundary. This report is codebase research, not a final design or acceptance contract.

## Findings

1. **Per-attempt lifecycle already exists.** `LLMAttemptDescription` and `LLMAttemptOutcome` in `src/agentmap/models/llm_attempt.py` represent resolved provider/model, attempt kind and retry ordinal, usage, cost, request ID, and classified error data. `src/agentmap/services/llm/attempt_lifecycle.py` owns physical-attempt lifecycle and evidence collection; `invoke_accounted_attempt` in `src/agentmap/services/llm/governed_accounting.py` wraps provider I/O and captures successful usage/cost. This is the strongest integration seam for one-record-per-attempt semantics; logging only the final high-level response would miss retries and failed attempts.

2. **Usage and provider identity are normalized.** `LLMResponse` and `LLMUsage` in `src/agentmap/models/llm_execution.py` carry resolved provider identity and nullable input/output token counts. `src/agentmap/services/llm_service.py` contains provider response normalization and existing metrics/telemetry recording. A file record should consume normalized evidence rather than parse provider-specific response shapes a second time.

3. **The existing logging service is the integration convention, but its purpose differs.** `src/agentmap/services/logging_service.py` supplies application logging; it does not by itself establish a dedicated append-only structured per-attempt daily file contract. A distinct file sink or a narrowly extended service contract is needed if the dedicated file, UTC rotation, and independent enablement requirements are to remain explicit.

4. **Configuration and DI are explicit seams.** `src/agentmap/services/config/app_config_service.py` provides app configuration, and `src/agentmap/di/container_parts/llm.py` constructs and wires the LLM service and its dependencies. The opt-in setting needs a safe false default and wiring that does not require OpenTelemetry to be installed or enabled.

5. **Error and privacy boundary needs a defined policy.** Attempt lifecycle data includes exception classification and provider response evidence. The change requests a sanitized error message but does not define redaction rules, maximum message length, or whether provider request IDs are allowed in the local log. Do not serialize raw request/response bodies, prompts, credentials, or arbitrary exception strings without a sanitization contract. Failure before any provider response must leave `response_datetime` absent; unavailable usage remains null rather than fabricated zero.

6. **Time and append semantics need explicit implementation choices.** UTC day partitioning should use an aware UTC timestamp captured per attempt. Concurrent async calls can target the same daily file, so append atomicity and failure isolation need to be considered. Logging failures should not silently convert a successful provider call into an LLM failure unless the product explicitly chooses that contract.

## Decisions

- **Affected contract/implementation:** extend the existing provider-attempt lifecycle and normalized `LLMAttemptDescription`/`LLMAttemptOutcome` evidence contract; wire an opt-in local sink through the LLM DI/configuration path. The public `ask` result contract need not change based on current evidence.
- **Extension versus new:** EXTEND the established attempt lifecycle and DI/configuration seams; introduce a dedicated sink only if the existing `LoggingService` cannot meet structured per-attempt, dedicated-file, and independent-OpenTelemetry requirements. Do not duplicate provider-specific token extraction.
- **Related capability reuse:** `E05-F06` usage/cost accounting is directly relevant and should be reused as the source of normalized token and resolved-provider data. Its `LLMResponse.cost` contract is not itself a durable attempt log. `E02-F03` telemetry/metrics is adjacent; reuse its normalized event data where appropriate, but keep local file logging independent of telemetry enablement/export.
- **Open questions for design/refinement:** choose the exact config key and output directory; define error sanitization and truncation; determine whether streaming attempts are in scope (the existing attempt model documents non-streaming physical attempts); specify write-failure behavior and concurrent append guarantees. The change-card scope does not answer these choices.
